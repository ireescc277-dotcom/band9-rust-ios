# 手环伴侣：同类 App 功能与产品方向研究

研究日期：2026-10-07。目标设备为小米手环 9 陶瓷特别版 `miwear.watch.n66tc`；客户端采用 Rust 协议核心与原生 SwiftUI，最低 iOS 17。

我们已经有可用的数据通道，接下来应把设备管理、健康记录和运动分析组织成日常使用的软件。下面把官方产品的功能、我们的数据能力、候选界面结构分开，避免把别家 App 的功能清单当成当前手环客户端已经具备的能力。

## 六类 App 分别解决什么问题

以下是按主要用途归类，并非互斥分类。官方功能随设备、地区、系统和订阅而变化；这里比较产品组织方式，不表示这些功能都能在 iPhone + 小米手环 9 上使用。

| 类型与代表 | 核心用途与官方功能 | 对本项目最有价值的借鉴 |
| --- | --- | --- |
| 设备管理型：Apple Watch App | “我的手表”集中设备设置；表盘图库用于选择外观与组件；“发现”提供使用说明。[Apple 官方](https://support.apple.com/guide/watch/change-the-settings-apd65b3ed73d/watchos) | 先看设备和连接，再进入分组设置；把细项放在二级页面。表盘、设置必须对应实际读写结果 |
| 健康档案型：Apple Health | 汇总与置顶分类、趋势、分类图表、数据来源、手工记录和单位管理。[Apple 官方](https://support.apple.com/en-ca/guide/iphone/-iphe3d379c32/ios) | 单指标有时间范围、来源和记录详情；用户决定首页关注哪些指标 |
| 设备与健康一体型：Mi Fitness / Band 9 | 活动与运动记录，心率、血氧、睡眠、压力，以及表盘、闹钟、天气、消息提醒等配套功能；iOS 兼容性逐项不同。[小米官方](https://www.mi.com/global/support/faq/details/KA-229921/) | 把健康和手环设置放在同一产品中；按实际设备能力显示入口，避免照搬其他型号功能 |
| 恢复与建议型：Zepp | 健康与运动追踪，Readiness、训练效果与恢复分析、个性化训练计划；部分洞察依赖订阅和特定数据。[Zepp 官方](https://www.zepp.com/technology) | 数据可以逐步形成解释和建议，但需要说明输入、算法和缺失条件，不能只有一个漂亮分数 |
| 运动训练型：Garmin Connect | 活动详情、长期指标、训练计划与自定义训练、路线、挑战、分享及装备使用记录。[Garmin 官方](https://www.garmin.com.sg/products/apps/garmin-connect-mobile/) | 一次运动是完整对象：概况、分段、曲线、地图、训练结果；历史记录需要检索和比较 |
| 日常健康型：Samsung Health | 活动、睡眠、饮食等日常追踪，并提供周报、挑战、用药管理和设备相关洞察。[Samsung 官方](https://www.samsung.com/us/apps/samsung-health/) | 把数据放回日常行为中；手工日志和提醒可以独立于手环存在，来源须清楚 |

这些产品的共同基础是“可靠记录 → 清楚呈现 → 历史比较”。训练建议、恢复评分和生态联动建立在不同的数据与系统能力上，不是换一套 UI 就能自动获得。

## 先确认数据从哪里来

| 来源层 | 可以组成的产品功能 | 本项目的边界 |
| --- | --- | --- |
| 手环直接返回的状态 | 电量、设备信息、连接状态、已配置的设置 | 蓝牙系统连接与应用认证是两个状态；字段未知不能当作关闭或零 |
| 手环记录文件 | 活动、心率、血氧、睡眠、运动历史 | 文件类别、版本、单位、时区分别解析；原始文件保存后再归一化 |
| 手环生成的统计或算法结果 | 日汇总、压力、活力分、部分训练指标 | 需要实际字段与设备样本；区分统计值、传感器样本和厂家算法结果 |
| 手机系统提供的数据与动作 | 健康库读写、手机定位、日历、通知或媒体联动 | 需要相应权限、平台 API 与签名能力；不能把 Android 的通知监听直接移植到 iOS |
| 用户主动填写 | 本 App 目标、运动备注、主观感受、生活日志 | 明确标为手工记录；修改 App 目标不等于已经改动手环目标 |
| 网络或外部服务 | 天气、地图内容、内容课程、云端备份 | 有独立来源、访问权限和潜在成本，不是从手环读取 |
| 本 App 自己计算 | 日周汇总、同比、达标率；未来的复杂评分 | 简单统计可解释；恢复等复杂评分必须先验证所需输入和方法 |

Apple 健康写入需要 HealthKit 配置与用户授权；通知需要研究配件通道与固件配合，而非让普通 App 任意读取其他 App 通知。普通 Band 9 的户外定位依赖手机。这些分别有独立的平台或设备前提。[HealthKit 配置](https://developer.apple.com/documentation/xcode/configuring-healthkit-access)、[ANCS 规范](https://developer.apple.com/library/archive/documentation/CoreBluetooth/Reference/AppleNotificationCenterServiceSpecification/Specification/Specification.html)、[小米 Band 9 FAQ](https://www.mi.com/uk/support/faq/details/KA-231124/)

## 当前能力与证据等级

本表依据当前仓库、用户真机记录及本轮通过 Wi-Fi 只读取得的档案核验结果；档案核验不等于新增了一次手环测量或同步。实机范围见 [README](../README.md)；协议实现见 [PROTOCOL](PROTOCOL.md)。

| 状态 | 功能范围 | 现在可以怎样开发 |
| --- | --- | --- |
| **已实机验证** | FE95 BLE 连接、认证、加密电量请求；活动文件下载、CRC、保存、重复同步去重；收到步数、距离、活动能量，以及分钟明细和手动测量两种来源的心率记录 | 做真实设备首页、连接状态、同步反馈、活动与心率历史；心率值和时间已与原始二进制字段独立核对，尚未与 Mi Fitness 逐项对照；实时心率控制仍未接入 |
| **解析已写，尚无本机实测样本** | 血氧、结构明确的睡眠分期 | 界面可接真实存储、空状态和图表；采到样本前不能报告这些指标已跑通 |
| **表盘读取已实机验证，其余待验** | 4/0 读取真实已安装列表及当前状态已验；4/1 切换读回和官方图片匹配已实现 | 构建 6 在用户手环读到 11 款表盘及唯一当前项。切换实际效果未验；App 尚未显示图片，官方目录并不覆盖每款已安装表盘 |
| **公开协议有依据，未接入本项目** | 压力、静息心率、站立小时、活力分；运动汇总、部分训练指标；找手环、闹钟和监测设置 | 按单个功能增量实现，先读再写，验证设备实际效果；上游共用代码不能证明本机全部支持 |
| **依赖 iOS 或外部来源** | HealthKit、手机 GPS、日历、天气、通知、媒体控制、后台自动同步 | 先确认系统能力及权限，再做前台、锁屏与恢复测试；目前不能承诺持续后台服务 |
| **需要额外数据与算法验证** | 自制恢复分、睡眠评分、训练建议、健康异常解释 | 先明确输入、缺失处理和算法来源；记录不足时不给分，不从分钟心率推算可靠 HRV |
| **当前不能列为可用** | HRV、ECG、原始 PPG、血压、体温、完整恢复评估 | RR 间期仅有上游文件线索；没有本机质量验证。ECG/血压/体温也不能从共用 schema 推断为 Band 9 硬件能力 |

最新只读核验确认原始二进制文件、JSON 档案、索引和 CRC 一致。心率已验证分钟明细与手动测量记录两种来源，不代表实时测量、静息心率、全天覆盖或全部文件版本都已验证。血氧和睡眠仍没有用户实机样本。

### 真实表盘与预览图的来源

手环的 4/0 列表提供真实表盘 ID、名称、当前状态和可删除标记，已在构建 6 实机验证。4/1 切换后重新读取列表确认当前项，界面不提前更改“当前表盘”；切换实现已完成，实际设备效果尚未验证。

图片另从小米官方匿名详情接口 `https://watch-appstore.iot.mi.com/api/watchface/prize/detail` 获取，参数是设备型号与已安装表盘 ID。接口发现线索来自 [get-mi-watchface 的 server.js](https://github.com/aurysian-yan/get-mi-watchface/blob/main/server.js)，官方接口用途已用公开样例核验。只接受回复主体 `data.id` 或 `data.id_v2` 与请求 ID 精确相等时的图片；不使用 `recommend_list` 中的推荐图替代，也不上传用户配对密钥。

官方目录图片是对应表盘的商品预览，不是手环实时截图，不反映当前时间、用户数据或每一种本地配置。独立查询三款真实已安装编号时，两款精确命中官方图片，当前表盘未命中；App 内图片仍未显示，需要继续排查型号与加载链路。无精确匹配或加载失败时显示无可用预览图。六款本机原创设计继续独立放在“本机设计预览”，只能收藏，不能上传到手环。

### 下一批协议能力的实际价值

| 能力组 | 可以带来的页面或操作 | 接入前必须确认 |
| --- | --- | --- |
| 实时心率、扩展心率历史、血氧 | 测量页、日曲线、最近值与测量时间；历史心率已读到两种来源 | 实时测量的开始/停止、超时、前后台行为尚未接入；扩大历史样本覆盖，核对无效值、采样间隔与官方显示；血氧仍待真实样本 |
| 睡眠 | 跨午夜时间线、阶段时长、日周变化 | 起止、午睡、阶段重叠、跨时区；不从汇总时长虚构阶段 |
| 日汇总扩展 | 静息心率、压力、站立小时、活力分 | 统计值与原始样本分开；站立小时不能显示成站立分钟 |
| 找手环 | 设备快捷振动操作 | 当前未接入；需要真实振动与停止验证 |
| 已有表盘与官方预览 | 真实表盘列表、当前项、切换，以及按 ID 匹配的官方图片；本版已接入 | 待本机核验列表与切换读回、图片匹配率；官方商品图不是实时截图；缺图不拿推荐图或本机设计顶替 |
| 闹钟、监测与提醒设置 | 可真正管理手环的设置页面 | 读取当前值、设备容量、修改后读回，保留未知字段和其他配置 |
| 运动文件 | 运动历史、详情、心率区间、配速曲线 | 按项目与文件版本适配，单位校验；只展示实际存在的指标 |
| 手机 GPS | 路线、运动地图、距离与定位状态 | 定位授权、前后台轨迹连续性、无定位时的状态；不宣称手环有独立 GPS |

## 三版产品定位与信息结构

三版已经组织为同一个 App 内可切换的界面，共用 `BluetoothModel` 与 `HealthArchive`，保留同一设备、密钥和记录；不是三个独立安装包。下表按当前已写入的页面整理，界面编译与实机使用仍由主构建统一验证。它们的差别体现在日常任务和页面层级，而不只在颜色。

| 维度 | A · Watch 管理版 | B · 健康生活版 | C · 数据分析版 |
| --- | --- | --- | --- |
| 首要问题 | “我的手环现在怎样，怎样设置？” | “今天活动了多少，收到了哪些健康记录？” | “长期变化怎样，现有数据有多完整？” |
| 主导航 | 我的手表 / 表盘图库 / 发现 | 今天 / 记录 / 我的手环 | 概览 / 数据 / 设备 |
| 首页 | 设备形象、认证和同步状态、电量、管理分组、手环当前表盘与管理入口 | 今日活动、最近健康记录、同步入口 | 今日步数、7/30 天活动趋势、记录合计、有记录日均、数据覆盖 |
| 二级页面 | 设备、连接与密钥、健康、记录、电池、数据导出、隐私和功能说明 | 按日期与指标查看记录、数据详情和来源；设备连接与导出 | 按指标筛选记录、样本数量、本机档案、原始文件与健康数据导出 |
| 视觉与操作重点 | 黑色与橙色，分组列表，熟悉的 Watch 层级 | 浅色与青绿，日常卡片，先看今天再看历史 | 深蓝与青色，图表与覆盖率，强调统计口径和数据缺口 |
| 当前实现与证据 | 设备连接、电量、活动同步、本地档案已验；真实表盘列表、切换与官方图已实现，待本机验证；原创设计仅本机预览 | 步数、距离、活动能量及历史心率；血氧和睡眠仍显示未收到记录 | 已收到活动的日汇总与趋势、包含心率的样本记录；缺样本日期不当作零计入平均 |
| 最关键的下一步 | 验证本版表盘列表、切换和图片匹配；继续找手环、闹钟与监测设置 | 心率与官方显示对照、血氧/睡眠实测、日汇总扩展、日常目标与记录细节 | 更多真实指标、时间与单位核对、数据完整性说明，随后纳入运动记录分析 |
| 不能提前承诺 | Apple Watch 专属生态、假设置开关、预览已经装到手环 | 自动生成医疗判断、缺输入的恢复/睡眠评分 | 样本数等于全天覆盖、未经验证的 HRV/恢复分、没有轨迹数据的地图 |

用户明确选择 Apple Watch App 作为界面参照，Watch 管理版因此作为默认入口；另外两版提供同一份数据的日常与分析视角。运动记录、路线和训练评估属于后续共享能力，不能用“数据分析版”这个名称暗示它们已经接通。

## 基于现有数据的开发顺序

下面是工程顺序建议，新增功能仍按真实设备能力落实。可以并行做界面和协议，但 UI 的完成不能替代真机验收。

| 阶段 | 具体产物 | 完成判断 |
| --- | --- | --- |
| 1 · 做好正在用的流程 | Watch 风格导航、设备主页、扫描/导入/连接、同步状态、活动历史、记录详情、错误恢复 | 用户能够完成连接到查看记录的全流程；错误可以定位并重试；页面没有示例数据冒充实测 |
| 2 · 补健康实测 | 扩大心率样本并与官方显示对照；采集血氧、睡眠样本；日汇总扩展 | 字段、单位、时间和官方页面可对应；重复同步不多记，缺失不显示零 |
| 3 · 做可操作的设备管理 | 先实测本版已接入的表盘列表、切换及官方图片匹配；再做找手环、闹钟和监测设置 | 每项有真实协议往返、错误处理、状态读回或设备效果验证；缺图明确说明，不能伪造预览 |
| 4 · 做完整运动记录 | 从已有运动文件开始适配；概况、曲线和筛选；再接手机 GPS | 每种已支持运动都有样本验证；地图来自真实轨迹；原始未知文件仍保留 |
| 5 · 接系统与外部服务 | HealthKit、日历、天气、通知路径、后台恢复 | 权限与签名满足要求；去重、锁屏、恢复与断连逐项验证 |
| 6 · 增加解释和个性化 | 周报、个人目标与备注、输入充分的趋势或评分 | 每个结论可追溯到来源和计算规则；缺输入时只显示已有信息 |

### 每个功能都遵守的呈现规则

- 最新值带时间；离线时保留上次记录并说明时间，不装作实时。
- 数值、日期、单位、设备与数据来源一起保存；每日汇总和分钟明细不能直接相加。
- “尚无记录”“未授权”“设备不支持”“解析未覆盖”“通信失败”是不同状态。
- App 本地偏好与手环设置分开；传输 ACK 不等于设备已经应用设置。
- 本机表盘设计按钮使用“收藏预览”，未实现上传前不显示“设为当前表盘”。
- 真实已安装表盘可以使用“设为当前表盘”，但必须等待设备状态读回；官方图片不能称为实时截图。
- 研究中的功能列在说明或开发记录中，正式页面只提供能够兑现的操作。
- 自动化测试、云端编译、安装成功、设备认证和实际数据效果分别报告。
